# Authentication Fix for Custom API Integration

## Problem Identified

The Laravel API was returning 401 Unauthorized errors when external applications tried to access it because:

1. **API Key Mismatch**: The external app was using `capi_d5b0e207fea9edbe28f4dda5f29ea6be907d0432f075439004d2be9ce1b4703a` but the database contained `capi_d4cd70450ca2182999b050614cf71b2425210a579a136681906bb2e42ba10034`

2. **Missing Authentication Middleware**: The `/api/orders` endpoint was protected by `auth:sanctum` middleware which only validates Laravel Sanctum tokens, NOT the custom API keys generated by the Custom API Integration feature.

3. **No Custom API Guard**: There was no authentication guard configured to validate custom API keys.

## Solution Implemented

### 1. Created Custom API Authentication Middleware

**File**: `app/Http/Middleware/AuthenticateCustomApi.php`

This middleware:
- Extracts the Bearer token from the Authorization header
- Validates that the token starts with `capi_` (custom API key prefix)
- Searches the database for an active Custom API integration with matching API key
- If found, authenticates the request and optionally sets the vendor's user as authenticated
- Stores integration details in request attributes for use in controllers

### 2. Created Dual Authentication Middleware

**File**: `app/Http/Middleware/AuthenticateSanctumOrCustomApi.php`

This middleware:
- Allows authentication via EITHER Sanctum tokens OR custom API keys
- Checks if the token starts with `capi_` to determine which authentication method to use
- Falls back to Sanctum authentication for regular users
- Enables both internal users and external applications to access the same endpoints

### 3. Registered Middleware Aliases

**File**: `bootstrap/app.php`

Added two new middleware aliases:
- `auth.custom_api`: For endpoints that only accept custom API keys
- `auth.sanctum_or_custom_api`: For endpoints that accept both Sanctum and custom API keys

### 4. Updated API Routes

**File**: `routes/api.php`

#### Added External API Routes (Custom API Key Only)
```php
Route::middleware('auth.custom_api')->prefix('external')->group(function () {
    Route::post('/orders', [OrderController::class, 'store']);
    Route::get('/orders', [OrderController::class, 'index']);
    // ... other routes
});
```

#### Added Test Authentication Endpoint
```php
Route::middleware('auth.custom_api')->get('/test-auth', function (Request $request) {
    // Returns authentication details for debugging
});
```

#### Modified Orders Routes to Support Both Auth Methods
Changed from `auth:sanctum` to `auth.sanctum_or_custom_api` for orders endpoints, allowing both internal users and external applications to access them.

## How to Generate a New API Key

1. Log in to the dashboard
2. Navigate to API Integrations → Custom API
3. Click "Generate API Key" button
4. Copy the new API key and store it securely
5. Update the external application with the new key

## Security Features

1. **Secure Key Generation**: Uses `random_bytes(32)` for cryptographically secure random keys
2. **Active Integration Check**: Only active integrations can authenticate
3. **Vendor Scoping**: If integration is linked to a vendor, only that vendor's data is accessible
4. **Bearer Token Format**: Requires proper `Authorization: Bearer` header format
5. **Prefix Validation**: Custom API keys must start with `capi_` to be validated

## Troubleshooting

### Error: "Unauthenticated. API key is required."
- Check that the `Authorization` header is present
- Ensure the format is: `Authorization: Bearer capi_...`

### Error: "Invalid API key format."
- The API key must start with `capi_`
- Check that you're not using a Sanctum token for custom API endpoints

### Error: "Invalid or inactive API key."
- The API key doesn't exist in the database
- The integration is inactive (is_active = false)
- Generate a new API key from the dashboard

### Error: 401 Unauthorized (with correct key)
- Check that the integration exists in the database
- Verify the integration is active
- Clear the application cache: `php artisan cache:clear`
